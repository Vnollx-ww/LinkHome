## 2. 模块定位

用户与家庭权限模块是整个系统的数据与权限基础。所有设备、房间、场景、告警、能耗数据均归属于某个家庭。用户必须先进入一个家庭空间，才能查看和控制该家庭下的智能设备。

## 3. 用户角色

| 角色 | 权限范围 | 典型用户 |
| :--- | :--- | :--- |
| 家庭创建者 | 拥有家庭最高权限，可转让、解散家庭 | 房主、系统初始化用户 |
| 管理员 | 可管理成员、房间、设备、场景、告警配置 | 家庭主要管理者 |
| 普通成员 | 可查看和控制允许范围内的设备，可执行场景 | 家庭成员 |
| 访客 | 仅在授权时间内控制指定设备或房间 | 临时保姆、亲友 |
| 未登录用户 | 只能访问登录、注册、隐私协议页面 | 新用户 |

## 4. 业务目标

- **降低使用门槛**：用户注册后可快速创建家庭并进入首页。
- **支持多人共用**：一个家庭可邀请多名成员共同控制设备。
- **权限边界清晰**：不同角色可操作的功能明确，避免误删设备、误改场景。
- **可追溯**：关键操作保留审计记录，方便排查问题。

## 6. 业务流程

### 6.1 首次使用流程

1. 用户打开 APP。
2. 进入登录/注册页。
3. 完成登录后，系统检查是否已有家庭。
4. 若无家庭，引导创建家庭。
5. 创建成功后进入首页。
6. 首页展示空设备状态，并提示添加设备。

### 6.2 邀请成员流程

1. 管理员进入“我的 - 家庭管理 - 成员管理”。
2. 点击“邀请成员”。
3. 选择邀请方式：二维码、邀请码、手机号。
4. 设置角色：普通成员或管理员。
5. 可选设置有效期。
6. 被邀请用户接受邀请后加入家庭。
7. 系统生成成员加入消息和审计记录。

### 6.3 权限校验流程

1. 用户发起操作，例如删除设备。
2. 后端读取用户在当前家庭下的角色。
3. 后端判断角色是否具备操作权限。
4. 有权限则执行操作并写审计日志。
5. 无权限则返回明确错误码与错误文案。

## 7. 页面与交互设计

### 7.1 登录页

- **页面结构**：顶部品牌 Logo，中部账号输入区，底部协议勾选与登录按钮。
- **输入项**：手机号/邮箱、密码、验证码入口。
- **交互反馈**：输入错误时在输入框下方展示红色提示；登录中按钮显示 loading。
- **视觉风格**：白底、智能家居渐变主色、圆角输入框。

### 7.2 家庭创建页

- **页面结构**：标题“创建你的家庭”，家庭名称输入框，家庭地址可选项，创建按钮。
- **默认值**：家庭名称可预填“我的家”。
- **空状态**：无家庭时必须进入该页面，不允许进入设备首页。

### 7.3 家庭管理页

- **页面结构**：家庭卡片、成员列表、房间入口、邀请入口、权限说明。
- **成员列表**：头像、昵称、角色、加入时间、更多操作按钮。
- **管理员操作**：修改角色、移出家庭、重新生成邀请码。

### 7.4 家庭切换组件

- **位置**：首页顶部左侧。
- **交互**：点击弹出底部 Sheet，展示用户加入的所有家庭。
- **状态**：当前家庭显示选中标记。

## 9. 异常场景

- **Token 过期**：自动刷新失败后跳转登录页。
- **家庭被删除**：提示“该家庭已不存在”，引导切换其他家庭或创建家庭。
- **成员被移除**：实时退出当前家庭，并清理本地家庭上下文。
- **权限不足**：按钮可置灰；若绕过前端调用接口，后端必须返回 `403`。
- **邀请码过期**：提示重新联系管理员获取邀请。

| member_invite_create | 创建邀请 | role、expireTime |

## 11. 验收标准

- **账号可用**：用户可完成注册、登录、退出、重新登录。
- **家庭闭环**：无家庭用户必须能创建家庭，有家庭用户可切换家庭。
- **权限有效**：普通成员不能添加或删除设备，接口层也必须拦截。
- **邀请可用**：管理员生成邀请码后，其他用户可加入家庭。
- **审计完整**：添加成员、移除成员、修改角色等操作均有记录。
