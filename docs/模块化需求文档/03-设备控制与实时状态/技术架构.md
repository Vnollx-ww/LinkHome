# 设备控制与实时状态模块技术架构

## 1. 技术目标

该模块通过 REST API 接收用户控制指令，通过后端指令执行器更新设备状态，并通过 WebSocket STOMP 将状态变化实时推送给家庭内在线成员。

## 2. 架构组成

| 组件 | 职责 |
| :--- | :--- |
| Control API | 接收控制请求，校验权限与参数 |
| Command Service | 创建指令、维护状态机 |
| Device Property Service | 更新设备属性快照 |
| Mock Device Executor | MVP 阶段模拟设备响应 |
| WebSocket Gateway | 推送设备属性变化和指令结果 |
| APP WebSocket Client | 订阅家庭频道并更新本地状态 |

## 3. 指令状态机

| 状态 | 说明 |
| :--- | :--- |
| CREATED | 指令已创建 |
| SENT | 指令已发送到执行器 |
| SUCCESS | 执行成功 |
| FAILED | 执行失败 |
| TIMEOUT | 执行超时 |
| CANCELLED | 已取消 |

## 4. API 设计

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| POST | `/api/devices/{deviceId}/commands` | 下发设备控制指令 |
| GET | `/api/devices/{deviceId}/properties` | 查询设备当前属性 |
| GET | `/api/devices/{deviceId}/commands` | 查询设备控制记录 |
| POST | `/api/families/{familyId}/devices/batch-commands` | 批量控制设备 |

## 5. 控制指令请求示例

```json
{
  "action": "setProperty",
  "properties": {
    "power": true,
    "brightness": 80
  },
  "clientRequestId": "uuid-from-app"
}
```

## 6. WebSocket 主题设计

| Topic | 说明 |
| :--- | :--- |
| `/topic/families/{familyId}/devices` | 设备新增、删除、在线状态变化 |
| `/topic/families/{familyId}/device-properties` | 设备属性变化 |
| `/topic/families/{familyId}/commands` | 指令执行结果 |
| `/topic/families/{familyId}/alerts` | 告警事件 |

## 7. 实现原理

1. APP 发送控制请求。
2. 后端校验用户是否有设备控制权限。
3. 后端校验设备属于该家庭且在线。
4. 后端创建指令记录。
5. 后端使用虚拟线程异步执行模拟逻辑。
6. 模拟执行器延迟 100-500ms 后更新属性。
7. 指令状态更新为成功或失败。
8. WebSocket 推送属性变化和指令结果。

## 8. 幂等设计

- APP 每次请求生成 `clientRequestId`。
- 后端对同一用户、同一设备、同一 `clientRequestId` 做唯一约束。
- 重复请求直接返回已有指令结果。

## 9. 并发控制

- 设备属性表使用 `version` 字段。
- 更新属性时校验版本，避免并发覆盖。
- 对同一设备的连续控制可按创建时间顺序执行。

## 10. 测试重点

- 控制在线设备成功。
- 控制离线设备失败。
- 重复请求幂等。
- WebSocket 断线重连后重新拉取快照。
- 多端同时控制同一设备的最终一致性。
