# 能耗统计与消息中心模块技术架构

## 1. 技术目标

该模块通过设备功率采样生成能耗统计，通过统一消息服务汇聚告警、设备、场景和系统事件。MVP 阶段使用 MySQL 存储采样与消息，后续大规模数据可迁移到时序数据库或数据仓库。

## 2. 架构组成

| 组件 | 职责 |
| :--- | :--- |
| Energy Collector | 定时采集或模拟生成设备功率数据 |
| Energy Aggregator | 按小时、天、月聚合能耗 |
| Energy API | 提供总览、趋势、排行接口 |
| Message Service | 创建、查询、已读消息 |
| Notification Preference Service | 管理用户通知偏好 |
| APP Message Store | 保存未读数和消息列表状态 |

## 3. API 设计

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/api/families/{familyId}/energy/overview` | 能耗总览 |
| GET | `/api/families/{familyId}/energy/trend` | 能耗趋势 |
| GET | `/api/families/{familyId}/energy/ranking` | 设备能耗排行 |
| GET | `/api/families/{familyId}/messages` | 消息列表 |
| GET | `/api/messages/{messageId}` | 消息详情 |
| PUT | `/api/messages/{messageId}/read` | 单条已读 |
| PUT | `/api/families/{familyId}/messages/read-all` | 全部已读 |
| GET | `/api/users/me/notification-preferences` | 通知偏好 |
| PUT | `/api/users/me/notification-preferences` | 更新通知偏好 |

## 4. 能耗采样实现原理

1. 定时任务每 1 分钟扫描在线设备。
2. 对具备 `currentPower` 属性的设备读取当前功率。
3. 对无功率属性但可估算的设备读取默认功率。
4. 写入能耗采样表。
5. 聚合任务按小时生成统计数据。
6. 查询接口优先读取聚合表。

## 5. 消息生成实现原理

- 告警服务创建告警后调用消息服务生成 `ALERT` 消息。
- 设备控制失败后生成 `DEVICE` 消息。
- 场景执行失败或部分失败后生成 `SCENE` 消息。
- 家庭邀请、角色变更生成 `SYSTEM` 消息。
- 能耗异常生成 `ENERGY` 消息。

## 6. 未读数策略

- APP 登录后拉取各类型未读数。
- WebSocket 收到新消息事件后本地未读数 +1。
- 已读后本地和服务端同步减少。
- 多端已读以后端状态为准。

## 7. 测试重点

- 能耗采样和聚合准确性。
- 消息分页、筛选、已读状态。
- 新消息实时推送和未读数更新。
- 已删除设备的历史消息展示。
