# 场景自动化模块技术架构

## 1. 技术目标

场景自动化模块基于规则引擎思想实现。MVP 阶段不引入复杂外部规则引擎，使用数据库规则配置 + Spring Service 判断 + 定时任务扫描 + 设备事件触发完成自动化。

## 2. 架构组成

| 组件 | 职责 |
| :--- | :--- |
| Scene API | 场景和自动化配置 CRUD |
| Rule Evaluator | 判断触发器和条件是否满足 |
| Action Executor | 将动作转换为设备控制指令 |
| Schedule Trigger | 处理时间触发规则 |
| Device Event Listener | 处理设备状态变化触发规则 |
| Execution Log Service | 记录执行结果 |

## 3. 规则数据结构

### 3.1 触发器 JSON 示例

```json
{
  "type": "DEVICE_PROPERTY",
  "deviceId": 1001,
  "property": "temperature",
  "operator": ">",
  "value": 30
}
```

### 3.2 条件 JSON 示例

```json
[
  {
    "type": "TIME_RANGE",
    "start": "10:00",
    "end": "22:00",
    "daysOfWeek": [1, 2, 3, 4, 5]
  }
]
```

### 3.3 动作 JSON 示例

```json
[
  {
    "type": "DEVICE_CONTROL",
    "deviceId": 2001,
    "properties": {
      "power": true,
      "temperature": 26,
      "mode": "COOL"
    }
  }
]
```

## 4. API 设计

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/api/families/{familyId}/scenes` | 场景列表 |
| POST | `/api/families/{familyId}/scenes` | 创建场景 |
| PUT | `/api/scenes/{sceneId}` | 修改场景 |
| DELETE | `/api/scenes/{sceneId}` | 删除场景 |
| POST | `/api/scenes/{sceneId}/execute` | 执行手动场景 |
| GET | `/api/families/{familyId}/automations` | 自动化列表 |
| POST | `/api/families/{familyId}/automations` | 创建自动化 |
| PUT | `/api/automations/{automationId}` | 修改自动化 |
| PUT | `/api/automations/{automationId}/enabled` | 启停自动化 |
| GET | `/api/automations/{automationId}/logs` | 执行日志 |

## 5. 执行流程

### 5.1 手动场景执行

1. 校验用户是否可执行场景。
2. 查询场景动作列表。
3. 创建执行批次记录。
4. 按顺序或并行调用设备控制服务。
5. 汇总每个动作结果。
6. 推送场景执行结果。

### 5.2 自动化触发

1. 时间调度或设备事件进入规则评估器。
2. 查询可能相关的启用规则。
3. 判断触发器是否匹配。
4. 判断条件是否满足。
5. 判断冷却时间。
6. 创建执行记录。
7. 调用动作执行器。

## 6. 防循环与限流

- 每条自动化规则设置 `cooldown_seconds`。
- 同一规则在冷却期内不重复执行。
- 自动化触发的设备变化事件需要携带来源，避免再次触发自身。
- 系统限制单条规则最多 20 个动作。

## 7. 测试重点

- 手动场景执行多个动作。
- 时间触发自动化。
- 设备属性变化触发自动化。
- 自动化启停状态生效。
- 设备删除后规则异常提示。
