# LinkHome 模块开发顺序与测试功能点文档

## 1. 文档目标

本文档用于指导 LinkHome 智能家居系统的模块化开发落地，明确各模块的推荐开发顺序、模块依赖关系、阶段性交付物、联调重点和测试功能点。

本项目建议采用“先基础能力、再设备闭环、再智能化、最后增强体验”的开发路径，避免在基础模型未稳定前过早开发复杂联动功能。

## 2. 总体开发原则

- **先后端基础，再 APP 页面**：优先建立用户、家庭、设备、权限和数据模型，避免前端反复返工。
- **先模拟设备，再真实协议**：MVP 阶段以数据库模拟设备完成完整业务闭环，后续再接入真实硬件。
- **先单设备控制，再场景自动化**：设备控制链路稳定后，再基于控制能力开发场景和自动化。
- **先功能正确，再体验优化**：核心状态、权限、异常、数据一致性优先于动画和视觉细节。
- **每个模块都要可独立验收**：模块完成后必须具备接口、页面、数据、异常和权限测试结果。

## 3. 推荐开发顺序

| 阶段 | 模块 | 优先级 | 依赖 | 目标 |
| :--- | :--- | :--- | :--- | :--- |
| 阶段 1 | 用户与家庭权限 | P0 | 无 | 建立登录态、家庭空间、成员权限基础 |
| 阶段 2 | 设备管理 | P0 | 用户与家庭权限 | 实现房间、设备添加、设备列表和设备资料维护 |
| 阶段 3 | 设备控制与实时状态 | P0 | 设备管理 | 打通控制指令、状态更新、WebSocket 实时同步 |
| 阶段 4 | 场景自动化 | P0 | 设备控制与实时状态 | 实现一键场景、定时规则、设备状态触发规则 |
| 阶段 5 | 安防监控与告警 | P1 | 设备状态、消息基础 | 实现告警触发、推送、确认、历史追溯 |
| 阶段 6 | 能耗统计与消息中心 | P1 | 设备状态、告警、场景 | 实现消息统一收敛和能耗统计分析 |
| 阶段 7 | 全链路联调与体验优化 | P0 | 全部模块 | 修复跨模块问题，优化 UI、性能和异常体验 |

## 12. 每个模块完成定义

一个模块只有同时满足以下条件，才认为开发完成：

- **接口完成**：核心 API 可调用，错误码清晰。
- **页面完成**：用户可在 APP 中完成主要操作。
- **权限完成**：无权限用户无法通过前端或接口越权。
- **异常完成**：空状态、失败状态、离线状态、网络异常都有处理。
- **数据完成**：数据库表、索引、初始化数据满足功能需要。
- **日志完成**：关键操作有日志或审计记录。
- **测试完成**：必测功能点全部通过。

## 14. 风险与注意事项

- **权限必须后端兜底**：不能只依赖 APP 隐藏按钮。
- **设备状态以后端为准**：APP 可以乐观更新，但必须接受 WebSocket 最终状态。
- **自动化要防循环**：规则之间互相触发可能导致无限执行。
- **告警要防刷屏**：必须设置冷却期和合并策略。
- **能耗数据要标记估算**：模拟或估算数据不能误导用户为真实精确数据。
- **删除设备要处理关联**：场景、自动化、告警规则、历史记录都要有明确策略。
