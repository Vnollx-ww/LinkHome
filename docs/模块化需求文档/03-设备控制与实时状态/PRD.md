# 设备控制与实时状态模块 PRD

## 1. 模块定位

设备控制与实时状态模块负责将用户操作转化为设备指令，并将设备执行结果实时反馈到 APP。该模块决定智能家居产品是否“响应快、状态准、反馈清楚”。

## 2. 用户目标

- 快速开关设备。
- 精准调节设备属性。
- 清楚知道指令是否已发送、执行中、成功或失败。
- 多端操作时状态能实时同步。

## 4. 控制面板 UI

### 4.1 通用设备详情页

- **顶部区域**：设备名称、房间、在线状态、更多设置按钮。
- **主控制区**：大号电源按钮，使用圆形卡片或渐变按钮突出状态。
- **属性控制区**：根据设备类型展示滑杆、选择器、开关、颜色盘。
- **底部区域**：运行记录、定时入口、自动化关联入口。

### 4.2 灯光控制面板

- 电源开关。
- 亮度滑杆，范围 1-100。
- 色温滑杆，范围 2700K-6500K。
- 颜色选择器，支持常用颜色圆点。
- 当前状态卡片显示“亮度 80% / 色温 4000K”。

### 4.3 空调控制面板

- 电源开关。
- 温度步进器，范围 16-30℃。
- 模式选择：制冷、制热、除湿、送风、自动。
- 风速选择：低、中、高、自动。
- 显示当前室温和目标温度。

### 4.4 窗帘控制面板

- 开、关、暂停三个快捷按钮。
- 开合百分比滑杆。
- 动画展示窗帘开合状态。

## 5. 状态定义

| 状态 | 含义 | UI 表现 |
| :--- | :--- | :--- |
| ONLINE | 在线可控 | 彩色图标、按钮可点击 |
| OFFLINE | 离线 | 灰色图标、按钮置灰 |
| CONTROLLING | 控制中 | loading、按钮临时禁用 |
| SUCCESS | 控制成功 | Toast、轻微震动、状态更新 |
| FAILED | 控制失败 | 错误 Toast、状态回滚 |
| FAULT | 故障 | 黄色/红色警示标识 |

## 6. 核心流程

### 6.1 单设备控制流程

1. 用户点击设备开关或调节属性。
2. APP 判断设备是否在线。
3. APP 发送控制指令到后端。
4. 后端创建指令记录，返回指令 ID。
5. APP 将设备显示为控制中。
6. 后端模拟执行或下发真实设备。
7. 后端更新设备属性。
8. 后端通过 WebSocket 推送状态变更。
9. APP 收到后更新 UI。

### 6.2 控制失败流程

1. 指令超时或设备离线。
2. 后端将指令状态标记为失败。
3. APP 收到失败事件。
4. APP 回滚本地状态。
5. 页面提示失败原因。

## 7. 异常场景

- **网络断开**：APP 顶部显示网络异常条，禁止新控制。
- **设备离线**：提示“设备离线，无法控制”。
- **指令超时**：超过 5 秒无结果则提示“控制超时”。
- **多端冲突**：以后端最新状态为准。
- **属性非法**：例如温度超范围，前后端均需校验。

## 8. 验收标准

- **反馈完整**：每次控制均有 pending、success 或 failed 状态。
- **状态准确**：WebSocket 推送后首页和详情页同时更新。
- **离线不可控**：离线设备所有控制入口置灰。
- **不同面板正确**：灯、空调、窗帘、插座展示不同控制控件。
