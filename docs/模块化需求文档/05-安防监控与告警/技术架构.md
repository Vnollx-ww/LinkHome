# 安防监控与告警模块技术架构

## 1. 技术目标

该模块通过设备属性事件驱动告警判断，并将告警事件分发到 APP、消息中心和审计日志。摄像头 MVP 阶段可使用模拟流地址或占位画面，后续接入 WebRTC、HLS 或 RTSP 转码服务。

## 2. 架构组成

| 组件 | 职责 |
| :--- | :--- |
| Camera API | 摄像头列表、直播信息、截图录像记录 |
| Alert Rule Service | 告警规则配置与判断 |
| Alert Event Service | 创建告警、更新告警状态 |
| Notification Adapter | 生成消息中心记录和推送事件 |
| WebSocket Gateway | 实时推送告警 |
| APP Alert Handler | 弹窗、震动、声音、页面跳转 |

## 3. 告警触发来源

- 设备属性变化事件。
- 定时巡检任务，例如设备长时间离线。
- 摄像头智能检测事件。
- 自动化规则主动创建告警。

## 4. API 设计

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/api/families/{familyId}/cameras` | 摄像头列表 |
| GET | `/api/cameras/{deviceId}/stream` | 摄像头直播信息 |
| POST | `/api/cameras/{deviceId}/snapshots` | 创建截图记录 |
| GET | `/api/families/{familyId}/alerts` | 告警列表 |
| GET | `/api/alerts/{alertId}` | 告警详情 |
| PUT | `/api/alerts/{alertId}/acknowledge` | 确认告警 |
| PUT | `/api/alerts/{alertId}/resolve` | 标记已处理 |
| GET | `/api/families/{familyId}/alert-rules` | 告警规则列表 |
| PUT | `/api/alert-rules/{ruleId}` | 修改告警规则 |

## 5. 告警判断实现原理

1. 设备控制或模拟器产生属性变化。
2. 发布内部 `DevicePropertyChangedEvent`。
3. 告警服务根据 familyId、deviceId、property 查询规则。
4. 判断阈值、状态、时间段和冷却期。
5. 命中后创建告警事件。
6. 创建消息记录。
7. 通过 WebSocket 推送。

## 6. 告警去重策略

- 同一家庭、同一设备、同一告警类型，在未处理状态下不重复创建高频告警。
- 可更新 `last_triggered_at` 和 `trigger_count`。
- 紧急告警允许持续提醒，但消息中心合并展示。

## 7. 摄像头实现建议

- MVP 使用设备属性中的 `streamUrl`。
- APP 使用视频播放器组件加载 HLS 地址。
- 如果没有真实流，展示模拟封面和“模拟监控中”。
- 后续真实硬件可通过流媒体服务将 RTSP 转 HLS/WebRTC。

## 8. 测试重点

- 烟雾、水浸、门窗告警触发。
- 告警确认和处理状态变更。
- 告警去重和冷却期。
- 摄像头离线 UI。
- 紧急告警强提醒。
