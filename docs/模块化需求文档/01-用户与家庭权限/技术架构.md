# 用户与家庭权限模块技术架构

## 1. 技术目标

用户与家庭权限模块需要为系统提供统一身份认证、家庭上下文、成员角色和操作权限校验能力。后端基于 Spring Boot 3.x + Spring Security + JWT 实现认证授权，APP 端基于 Expo Router + Zustand 管理登录态和当前家庭。

## 2. 架构职责

| 层级 | 职责 |
| :--- | :--- |
| APP 展示层 | 登录页、家庭管理页、成员管理页、家庭切换弹窗 |
| APP 状态层 | 保存 accessToken、refreshToken、当前家庭、用户资料 |
| API 层 | 提供认证、家庭、成员、邀请、权限查询接口 |
| 领域服务层 | 处理注册登录、Token 刷新、家庭创建、角色变更 |
| 权限拦截层 | 基于用户、家庭、角色、资源归属做权限判断 |
| 数据层 | 存储用户、家庭、成员、邀请、审计日志 |

## 3. 核心数据模型

- **User**：系统用户主体。
- **Family**：家庭空间，承载设备、房间、场景、消息。
- **FamilyMember**：用户与家庭之间的关系，包含角色和状态。
- **FamilyInvite**：邀请记录，包含邀请码、角色、过期时间。
- **AuditLog**：关键操作日志。

## 4. 登录认证方案

### 4.1 Token 设计

- **accessToken**：短有效期，用于接口调用。
- **refreshToken**：长有效期，用于续期。
- **Token Claims**：包含 userId、tokenType、issuedAt、expireAt。
- **家庭权限不写死在 Token 中**：角色可能变更，接口每次基于数据库或缓存查询当前家庭角色。

### 4.2 APP 登录态管理

- 登录成功后将 Token 存入安全存储。
- Zustand 保存内存态：`userInfo`、`currentFamilyId`、`familyList`。
- Axios 请求拦截器自动携带 `Authorization: Bearer <token>`。
- 响应拦截器遇到 `401` 时尝试刷新 Token。

## 5. 权限实现原理

### 5.1 权限判断维度

- 用户是否登录。
- 用户是否属于当前家庭。
- 成员状态是否为正常。
- 成员角色是否满足操作要求。
- 操作资源是否归属于当前家庭。

### 5.2 后端实现建议

- 使用 Spring Security 过滤器解析 JWT。
- 使用 `@RequireFamilyRole` 自定义注解声明接口所需角色。
- 使用 AOP 在 Controller 或 Service 层进行家庭角色校验。
- 所有写操作统一记录审计日志。

## 6. API 设计

| 方法 | 路径 | 说明 | 权限 |
| :--- | :--- | :--- | :--- |
| POST | `/api/auth/register` | 注册 | 公开 |
| POST | `/api/auth/login` | 登录 | 公开 |
| POST | `/api/auth/refresh` | 刷新 Token | 公开 |
| GET | `/api/users/me` | 当前用户资料 | 登录 |
| POST | `/api/families` | 创建家庭 | 登录 |
| GET | `/api/families` | 我的家庭列表 | 登录 |
| PUT | `/api/families/{familyId}` | 修改家庭资料 | 管理员 |
| GET | `/api/families/{familyId}/members` | 成员列表 | 成员 |
| POST | `/api/families/{familyId}/invites` | 创建邀请 | 管理员 |
| POST | `/api/family-invites/{code}/accept` | 接受邀请 | 登录 |
| PUT | `/api/families/{familyId}/members/{memberId}/role` | 修改角色 | 管理员 |
| DELETE | `/api/families/{familyId}/members/{memberId}` | 移除成员 | 管理员 |

## 7. 缓存策略

- 用户资料可在 APP 本地缓存。
- 当前家庭角色可使用 Redis 或 Caffeine 做短期缓存。
- 角色变更、成员移除、家庭解散时必须主动清理缓存。

## 8. 安全设计

- 密码必须使用 BCrypt 哈希存储。
- 登录失败次数过多时进行限流。
- 邀请码必须具备过期时间和使用次数限制。
- 创建者角色不能被普通管理员移除。
- 家庭解散、角色降级等高危操作建议二次确认。

## 9. 与其他模块关系

- 设备管理模块依赖家庭成员权限判断。
- 场景自动化模块依赖管理员权限创建和修改规则。
- 告警模块根据家庭成员关系决定推送对象。
- 消息中心根据用户与家庭关系过滤消息。

## 10. 测试重点

- Token 过期、刷新、退出登录流程。
- 普通成员越权调用管理接口。
- 成员被移除后继续调用接口。
- 多家庭切换后的数据隔离。
- 邀请码过期、重复使用、角色变更。
